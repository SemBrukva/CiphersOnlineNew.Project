## 0. TL;DR

**Где мы сейчас.** У проекта сильный фундамент: 57 опубликованных инструментов в 5 каталоговых категориях + отдельный хаб авто-солвера, локализация на 8 языков (~456 tool-страниц), canonical/hreflang, структурированные данные, sitemap, `llms.txt`, manifest, внутренний REST API + OpenAPI, rate limiting, аккаунты/избранное/кабинет, админка, рекламные слоты и собственная аналитика операций. Информационный слой уже запущен: 50 терминов и 5 гайдов × 8 локалей. Реализованы permalink со state, embed-виджеты и универсальный авто-солвер.

**Текущее узкое место — не базовая техника, а доказуемый рост.** Не хватает семантики и Search Console-данных по большинству локалей, законченного контент-кластера, регулярного цикла «запрос → страница → позиция/CTR → успешная операция», сильного workspace/обучающего сценария и системной дистрибуции. Следующий этап — не наращивать число страниц вслепую, а повышать долю страниц, которые получают показы, клики и успешные операции.

**Стратегия к Топ-1** строится на трёх опорах, сочетание которых проект должен превратить в измеримое преимущество:

1. **Самый широкий и лучше всего локализованный каталог инструментов** (охват спроса на 12+ языках).
2. **Информационный авторитет** — глоссарий + гайды + разборы, которые ранжируются и кормят tool-страницы (E-E-A-T).
3. **Продуктовая дифференциация** — лучший beginner-first путь от неизвестного ciphertext к объяснённому результату на нескольких языках, затем workspace, мультимодальный ввод и API.

Монетизация диверсифицируется: **API (RapidAPI + ключи) → Pro-подписка (freemium) → партнёрки → оптимизированная реклама**.

## 1. Видение и позиционирование

**Одной фразой:** _«Ciphersonline — место №1, где любой человек в мире может зашифровать, расшифровать, распознать и _понять_ любой шифр — на своём языке, бесплатно, с первого клика.»_

Три аудитории и их job-to-be-done:

| Сегмент | JTBD | Что им нужно от продукта |
|---|---|---|
| **Массовый / любители** (квесты, escape-room, geocaching, TikTok-загадки, школьники) | «быстро раскодировать/закодировать записку» | скорость, распознавание «что это за шифр», мобайл, шаринг |
| **Учащиеся / преподаватели** | «понять, как работает шифр, и показать другим» | пошаговая визуализация, история, встраиваемые виджеты |
| **Разработчики / безопасники** | «встроить кодирование/хеширование в свой процесс» | API, batch, CLI, надёжность, docs |

Конкурентное окно нельзя строить на тезисе «этого ни у кого нет». CyberChef уже предлагает сотни операций, цепочки и автоматический `Magic`; Boxentriq — автоанализ текста/файлов и workspace; dCode силён широтой. Рабочая гипотеза CiphersOnline: **сделать путь новичка заметно проще, объяснять результат, поддерживать локальные языковые модели и связывать solver → tool → guide → следующий шаг**. Эту гипотезу нужно подтверждать сравнительными UX-тестами и метриками, а не декларацией.

## 3. Опора A — SEO и охват спроса

### A1. Информационный слой (наибольший недобор трафика) 🔥

Сейчас ловится только transactional-intent. Мимо проходит весь informational-объём: «что такое шифр X», «как расшифровать без ключа», «виды шифров», «шифры для квеста», «X vs Y».

Три типа информационных страниц (два уже запущены):

1. ✅ **Глоссарий терминов** (`/glossary/{term}`): 50 терминов × 8 локалей, `DefinedTerm` schema и перелинковка.
2. 🟡 **Гайды / статьи** (`/guides/{slug}`): 5 из 18 запланированных статей × 8 локалей, `Article` schema, guide→tool/term/guide и tool→guide.
3. ❌ **Сравнения и decision pages**: создавать только для подтверждённых запросов и реального различия сценариев. Не генерировать все пары алгоритмов программно — это риск тонкого/масштабированного контента.

**Реализация:** инфраструктура уже готова (`GuideRepository`, `GuidesController`, `guide-article.v1`, `guide_related.php`, sitemap, llms.txt, `guides:validate`). Контент хранится в файлах и проходит через Git/PR, поэтому CRUD в админке в текущем scope не нужен. Ближайшая задача — закончить 13 оставшихся статей, проверить кластеры по реальному спросу и измерить переходы в инструменты.

**KPI:** не обещанный процент трафика, а доля опубликованных материалов с показами/кликами за 90 дней, переходы guide→tool и успешные операции после входа через информационную страницу.

### A2. Семантика на все 8 языков + переоптимизация meta 🔥

Контент на de/es/fr/it/pt/tr есть, но это преимущественно перевод, а не таргетинг под локальный спрос. Семантическое ядро собрано только для ru/en.

- Прогнать сбор семантики (Yandex Wordstat для ru-рынков, Google Keyword Planner / DataForSEO / Ahrefs для латиницы) по остальным 6 языкам → `storage/semantic-core/{de,es,fr,it,pt,tr}`.
- Переписать `meta_title` / `meta_description` / первый экран под локальные формулировки (не дословный перевод: напр. FR ищет «déchiffrer», а не кальку с англ.).
- Использовать `content_recommendations` из семантики (уже есть в схеме) как чеклист.

**KPI:** рост CTR и позиций на неанглоязычных рынках; де-факто разблокировка уже написанного контента.

### A3. Новые языки — расширение после доказательства качества ⭐

Архитектура делает добавление языка дешёвым (перевод JSON + словарь + `APP_LANGUAGES`). Приоритет по объёму спроса и низкой конкуренции:

1. **pt-BR** (отделить от pt-PT — крупнейший рынок Португалоязычных).
2. **id** (Индонезия — огромная аудитория головоломок, низкая конкуренция).
3. **ja**, **ko** (высокий интерес к шифрам/аниме-загадкам).
4. **zh-Hans**, **ar**, **hi**, **pl**, **nl**, **vi**.

Процесс: семантика и SERP-анализ → локализация топ-кластера → редакторская проверка носителем/экспертом → индексирование → оценка спроса и качества → только затем тиражирование каталога. Машинный перевод без добавленной ценности нельзя считать безопасным SEO-масштабированием.

**KPI:** показы, клики и успешные операции на локализованный кластер; доля страниц с органическими показами через 90 дней; стоимость редакторской проверки на одну результативную страницу.

### A4. Технические SEO-докрутки ▫️

- **Per-tool OG-изображения** (сейчас один `og-image.jpg`): генерировать динамически (PHP GD/Imagick или headless-скрин) → лучше CTR в соцсетях/выдаче. Кэшировать в `public/`.
- ✅ **Self-host шрифта Inter** — вариативный `@fontsource-variable/inter`, бандлится через Vite в `public/build/assets/` (same-origin woff2, `unicode-range` по subset'ам), Google Fonts `<link>`/`preconnect` убраны из `main.tpl`/`embed.tpl`, CSP сужен (без `fonts.googleapis.com`/`gstatic.com`). Устранён render-blocking внешний запрос → LCP.
- ✅ `WebApplication` уже есть на tool-страницах. Не добавлять `HowTo` ради Google: этот rich result снят; `FAQPage` также не является заметным rich-result каналом для обычных сайтов. Оставлять schema только если она точно отражает видимый контент и полезна другим потребителям.
- Не добавлять `SearchAction` ради sitelinks search box: Google удалил этот элемент выдачи в 2024 году.
- **Sitemap:** выставлять реальный `lastmod` только при существенном изменении страницы; убрать ложную текущую дату у неизменённых файлов. `priority` и `changefreq` не считать SEO-рычагами — Google их игнорирует.
- **Индексация state URL:** permalink использует fragment и не создаёт отдельный HTTP URL. Для query-параметров опираться на чистый canonical; `robots.txt Disallow` сам по себе не гарантирует исключение URL из индекса.

### A5. Search intelligence и цикл экспериментов 🔥

- Подключить Google Search Console API/экспорт и объединить с Yandex Webmaster и внутренними `tool_usage_events` по ключу `locale + landing page + query cluster`.
- Дашборд по локали и типу страницы: impressions, clicks, CTR, average position, indexed pages, successful operations, guide→tool CTR, share/embed rate.
- Вести журнал SEO-релизов и сравнивать когорты страниц через 28/56/90 дней. Не приписывать рост одному изменению без контрольной группы или хотя бы сопоставимой когорты.
- Ввести правило обновления/слияния: страница без показов после достаточного окна не размножается на новые языки автоматически.

### A6. Доверие и проверяемость контента ⭐

- Для современных алгоритмов и dev-инструментов ссылаться на первичные стандарты (RFC/NIST), указывать ограничения и безопасные сценарии применения.
- Добавить редакционную политику, дату содержательного обновления, автора/ревьюера и журнал проверки примеров.
- Автоматически проверять примеры через API, битые внутренние ссылки, hreflang-пары и соответствие schema видимому контенту.

Порядок далее по спросу/усилию: **Random string** → **Diceware passphrase** → **Text case converter**.

**Реализация:** ваш паттерн уже отработан (миграция + `ToolRegistry` + декодер + контент-JSON — см. память `project-cipher-architecture`). Каждый инструмент = тираж по шаблону.

**KPI:** не само число инструментов, а число новых query-кластеров с показами и успешными операциями. Цель 100+ допустима только как следствие подтверждённого спроса.

### B2. «Умный» авто-солвер — киллер-фича 🔥

✅ Реализован `/cipher-solver`: определение кандидатов, поддерживаемый brute-force/cracker, n-gram-скоринг и ранжированный результат. Это основной вход для запроса «у меня записка, что это?», но качество ещё нужно измерять системно.

- Зафиксировать benchmark по типам шифров, длинам текста и 8 языкам: top-1 accuracy, top-3 recall, доля уверенно неверных ответов, latency.
- Показывать, почему выбран кандидат, уровень уверенности и безопасный следующий шаг; не выдавать эвристику за гарантированную расшифровку.
- Расширять набор атак только после замера вклада в benchmark и стоимость вычисления.

**Следующий шаг:** измерить качество top-1 кандидата по языкам и типам входа на фиксированном benchmark-наборе. Конкуренты уже предлагают identifier/automatic analysis, поэтому преимущество должно быть в точности, объяснимости и следующем действии, а не в самом факте автоопределения.

## 5. Опора C — Трафик и виральность

### C1. Sharable permalink со state ✅
Состояние уже кодируется в fragment `#s=...`. Даёт:
- Виральность: пользователь делится ссылкой на готовую расшифровку → трафик + естественные беклинки с форумов/Reddit/квест-сообществ.
- Внутренний UX: сохранённые состояния, «поделиться результатом».
- Реализация использует `#s=...`: fragment не отправляется серверу и canonical остаётся чистым. Если появятся серверные share pages, отдельно решить TTL, privacy, `noindex` и удаление пользовательского содержимого.

### C2. Встраиваемые виджеты (embed / iframe) ⭐
✅ `/embed/{category}/{tool}` и генератор iframe-кода реализованы. Ценность — дистрибуция, брендовые переходы и использования с source=`embed`; iframe нельзя автоматически считать dofollow-бэклинком. Следующий шаг: галерея embed-примеров, адаптивная высота, versioned contract и отчёт по доменам/переходам без сбора лишних персональных данных.

### C3. Публичный API как канал привлечения ⭐
Страница `/api` + листинг на RapidAPI тянет разработчиков и ссылки (см. монетизацию D1). Docs уже генерируются (`openapi.json`).

### C4. Контент-дистрибуция и линкбилдинг ▫️
- Ответы/присутствие в сообществах: r/codes, r/puzzles, geocaching, escape-room форумы, Stack Exchange (Puzzling/Crypto).
- Программные PR-поводы: «индекс популярности шифров» на основе вашей аналитики использования (`/api/analytics/use`) — уникальные данные → цитируемость.
- Digital PR вокруг образовательного контента (глоссарий/гайды).

### C5. Retention: включить аккаунты ▫️
`USER_REGISTRATION` сейчас `false`. Не включать регистрацию до появления дополнительной ценности: история, сохранённые workspace/recipes, синхронизация и понятные privacy controls. Manifest есть, но полноценный offline/install UX и service worker ещё не реализованы.

## 6. Опора D — Монетизация (диверсификация)

Порядок — по потенциалу и готовности инфраструктуры.

### D1. Платный API — самый недооценённый актив 🔥
У вас **уже есть** REST API на каждый инструмент, OpenAPI-спека и rate limiting. Не хватает только продуктовой обвязки:
- API-ключи + тарифы (free / pro / business) по объёму запросов.
- Листинг на **RapidAPI** (быстрый канал платящих разработчиков) + собственный биллинг позже.
- Тарифицируемое: encode/decode/hash/identify/solve, batch, приоритет.
- Инфраструктура ключей ложится на существующие middleware (`ApiAuthMiddleware`) + `rate_limit.php` (лимиты уже по маршрутам).

**Условие запуска:** сначала публичная документация, API keys, usage metering, abuse controls и проверка спроса на бесплатном лимите. Биллинг не должен опережать доказательство того, что разработчики возвращаются к API.

### D2. Freemium «Pro»-подписка ⭐
Rate limit + аккаунты = естественный gate. Pro-ценность:
- Без рекламы, без лимитов, batch/файлы, история и сохранённые workspace, приоритетный авто-солвер, экспорт, приватность.
- Кабинет и избранное уже есть — надстроить биллинг (Stripe/Paddle через `HttpClient`).

### D3. Контекстные партнёрки ⭐
На history/FAQ/guide-блоках (нативно, конверсит лучше баннеров):
- Книги по криптографии (Amazon Associates), escape-room киты, курсы по кибербезопасности/CTF, менеджеры паролей, VPN (на dev-страницах).
- Lead-gen для образовательных платформ.

### D4. Оптимизация текущей рекламы ▫️
Слоты уже есть (`after_hero`, `after_first_block`, `after_faq`) для AdSense и РСЯ. Докрутка:
- A/B плейсментов и плотности **без ущерба Core Web Vitals** (реклама не должна ронять LCP/CLS — иначе просядет SEO).
- Гео-таргетинг сети: РСЯ на ru-рынках, AdSense на остальных (частично заложено).
- Отключать рекламу для Pro/залогиненных как часть ценности подписки.

**Целевую структуру выручки** задавать после 2–3 месяцев фактических данных по RPM, API activation/retention и willingness-to-pay. До этого проценты будут не планом, а произвольным прогнозом.

## 8. Проверяемая дифференциация

Статическую таблицу «у конкурента есть/нет» быстро делает неверной один релиз. Вместо неё вести ежеквартальный benchmark на 10–15 реальных задачах для каждой аудитории.

| Измерение | Метрика | Целевой сигнал преимущества |
|---|---|---|
| Неизвестный ciphertext | top-1/top-3 accuracy, время до полезного результата | пользователь получает объяснённый кандидат быстрее конкурентов |
| Новичок | task success rate без инструкции, число ошибок/возвратов | задача решается с первого экрана |
| Локализация | качество top-10 query-кластеров и solver accuracy по языкам | локальная версия не является переводной копией EN |
| Обучение | completion шага, переход guide→tool, повторное упражнение | пользователь понимает преобразование, а не только копирует ответ |
| Workspace | сохранённые/повторно открытые recipes, D7/D30 retention | сайт становится рабочим местом, а не одноразовым калькулятором |
| Дистрибуция | активные embed-домены, share→visit→operation | пользовательские действия приводят новых пользователей |
| API | activation, successful calls, week-4 retention | есть повторяемый developer use case до включения оплаты |

**Формула лидерства:** локальная релевантность × точность solver × понятность следующего шага × глубина рабочего сценария × дистрибуция. Каждая часть должна иметь baseline и сравнительный тест.

## 10. Риски и как их держать под контролем

| Риск | Митигинг |
|---|---|
| Реклама роняет Core Web Vitals → просадка SEO | лимит плотности, lazy-загрузка, мониторинг CWV в CI |
| Масштабированный перевод/AI-контент без добавленной ценности | semantic-first rollout, редакторская проверка, малые когорты, не индексировать недоведённые страницы |
| Тяжёлые расчёты (solver/cracker) кладут воркеры | очередь (`QueueManager`) + rate limit (паттерн уже есть) |
| State URL или share pages создают дубли/утечку текста | fragment для локального state; для серверных shares — privacy, TTL, canonical/noindex и удаление; не полагаться только на robots.txt |
| Размывание нишевого бренда «магнитами» (генераторы паролей) | отдельная категория `/tools`, отдельная перелинковка |
| Злоупотребление публичным API | ключи + тарифы + лимиты + мониторинг |
| Юридическое: хеши/крипто как «взлом» | дисклеймеры (в семантике уже есть рекомендации «не обещать взлом») |
| План оптимизирует vanity metrics | gate по successful operations, retention и query coverage; число страниц/инструментов не является результатом само по себе |

## 12. Основания актуализации SEO и конкурентных допущений

- Google удалил sitelinks search box и поддержку соответствующего `SearchAction`: [Google Search Central](https://developers.google.com/search/blog/2024/10/sitelinks-search-box).
- `HowTo` rich results сняты; FAQ rich results для обычных сайтов были ограничены, а затем удалены из Google Search: [история изменений Search Central](https://developers.google.com/search/updates).
- Google использует достоверный `lastmod`, но игнорирует `priority` и `changefreq`: [рекомендации по sitemap](https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping).
- `robots.txt Disallow` не гарантирует исключение URL из индекса; для дублей важен canonical: [robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro), [canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).
- Массовый перевод/генерация страниц без добавленной ценности попадает в зону риска scaled content abuse: [spam policies](https://developers.google.com/search/docs/essentials/spam-policies).
- Контрольные точки конкурентов на дату аудита: [CyberChef](https://gchq.github.io/CyberChef/), [Boxentriq Analyze Anything](https://www.boxentriq.com/code-breaking), [Boxentriq Cipher Identifier](https://www.boxentriq.com/analysis/cipher-identifier).
